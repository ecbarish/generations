# Wildbond: references, decisions and lessons

For every incoming AI. Compiled for Evan on 2026-10-18 from the project’s recorded research and his decisions. Start with the [current handoff](../WILDBOND-HANDOFF.md) for live code, PR dependencies and launch instructions, then the [cast guide](../lore/wildbond-cast-guide.md) before writing characters. This page indexes existing investigations; it does not claim a fresh verification of external sites or their terms.

## What we are making

A private Pokémon-style RPG with Wildbond’s own interconnected region, people, mysteries, ranch and eventual original creatures. Reuse polished existing ingredients to reach enjoyable play quickly. Gen 1–4 provide the primary creature/battle-art references; Platinum, HeartGold/SoulSilver and Emerald provide combat readability. Pokémon Battle Advanced (PBA) provides the leading world-presentation reference. Standard turn-based battles are the current implementation direction; real-time dodging remains an explored alternative, not a second committed combat project.

Evan also wants the presentation and controls to feel more modern as the journey progresses, from Game Boy toward Switch. That is a long-term direction. Development day/night toggles and a modern-looking test scene are not completed story-era unlocks. Follow the lore’s restoration sequence before making those effects part of the adventure.

The [private-art report](wildbond-private-sprites/README.md) and `tools/wildbond-private-sprites.py` record pinned revisions and validated geometry. Locate the actual external pack via the ignored local locator described in the handoff. Keep imported Pokémon originals, derivatives and actual-art screenshots outside Git/public exports. Public code and fallback/original captures remain reviewable without that pack. Modifying a Pokémon sprite does not change this boundary; regional forms are future proposals.

Reuse systems already in this repository first: the registry separates original/imported identity; the journey catalogue/profile/bag/rounds code powers the current opening; the town/environment studies feed its presentation. PokeAPI supplies structured data/art rather than a complete battle engine. The reviewed fan demo has not supplied a confirmed licensed transplantable engine. Do not describe a shortlist, metadata inspection or source-code license as an asset license.

## Lessons to carry into the next task

1. **Preserve identity.** Species save IDs, source data and rendered art are separate. Original starters now have original IDs, stats and moves; do not use renamed Pokémon proxies as canonical originals. See [registry](wildbond-registry.md), [runtime contract](wildbond-registry-runtime/README.md) and [live starter adapter](wildbond-live-starters/README.md).
2. **Measure animation rather than guessing.** Individual frame rectangles and foot anchors prevent chopping. Keep a fixed body scale from a neutral pose. Distance-driven gait, directional poses and short pauses make companions feel alive. See [actor polish](wildbond-actor-polish/README.md) and `wildbond-godot/tests/starter_sprites/frames.json`. The generated sheets still need art acceptance; shaders do not make them hand-cleaned native pixel atlases.
3. **Keep actors readable in the world.** Ground feet, fade occluders and check service counters/sightlines with the actual trainer and follower. A great isolated sprite can disappear behind a tree in play. The actor and layout reports retain the concrete fixes.
4. **Build one useful outing.** The [opening chapter](wildbond-opening-chapter/README.md) connects services, catches, battles and a return to Maren. Extend the approved regional graph from there. Most of the full adventure’s ranch/story/era systems are not integrated into this chapter yet.
5. **Treat saves as part of the feature.** Follow the current handoff’s schema/backup rules, use isolated test paths and never run old/new profile writers together. A working battle screenshot does not prove migration or return-to-world safety.
6. **Keep evidence honest.** Automated checks establish specific behavior, not fun or art approval. Report fallback/private presentation separately. Research inspection did not establish PBA performance or recover its exact lighting implementation. Historical test counts must not be presented as a new run.

## For an AI joining now

Read the handoff and this guide, reconcile live PR heads, then use only the sources your task needs. Read the [cast guide](../lore/wildbond-cast-guide.md) and writer ledger before dialogue. Inspect current scene code as well as source lore: later-region canon does not mean that region is already walkable in the new chapter. The [Claude task](wildbond-live-starters/CLAUDE-TASK.md) defines the sprite-review scope; inspect its current PR before duplicating work.

If a chat attachment or source board is unavailable, use its repository provenance/approved reference or ask for that exact missing reference. Do not invent a replacement and call it approved. Record new findings, their limits and the decision they support in the appropriate report, then add a short route here when it teaches something reusable.
